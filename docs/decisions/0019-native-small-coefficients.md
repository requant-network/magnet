# ADR 0019: Independent native small-coefficient baseline

Date: 2026-10-09. Status: accepted for local research only.

## Context

Python logical counters are not calibrated hardware work. The non-unit sparse
family needs an independently implemented native search baseline and fresh
schedules before hardware comparisons or portable work claims.

## Decision

Add separate bounded SCP1/SCR1 process interfaces and safe Rust enumeration for
spec21. Preserve order, nonprimitive validity, exact sequential caps, all ledgers
and independent exhaustion. Bound batch consumption/pipes and reject the entire
exchange on malformed frames, diagnostic output, exit or semantic mismatch.
Reconcile each reply against Python; never silently substitute a fallback.

Use tiny Cartesian/full-ledger audits and a maximum-shape actual-search fixture
whose final columns contain late proofs. Freeze104 cases with three repetitions
and a separate192-acquisition fresh/control campaign on new seed labels.
Preserve each positive timing and three explicitly separate scopes. Freeze
sources, release binaries and exact raw bytes; invalidate evidence before builds.

## Consequences

All768 native/reference comparisons and48 tiny-box audits agree. Native search
exhausts18912 maximum-shape candidates and returns all six independent-oracle
proofs including a late scalar copy. Local tests and frozen campaigns pass.
Native internal samples are lower in the selected seeded cases, but different
timing boundaries and full host reference reconciliation preclude an end-to-end
speedup ratio. No portable winner or production PoW pricing follows.

Fresh carry succeeds54/515; controls486/486. These are correlated finite pool
observations under capped acquisition, not independent success probabilities.
The next hardware comparison must match domain, caps, output and timer scopes.
No consensus, validity, GPU API or monetary parameter changes. See the
[report](../research/native-small-coefficients-v1.md).
