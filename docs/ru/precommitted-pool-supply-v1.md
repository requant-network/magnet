# Точная модель переноса готовых векторов

Вторичный русскоязычный обзор, 9 октября 2026 года.
[Основной отчёт на английском](../research/precommitted-pool-supply-v1.md).

Следующий блок исследования выполнен: добавлена точная модель вероятности того,
что заранее подготовленные короткие векторы подойдут к новой матрице. Она учитывает
не только число векторов, но и зависимости между ними по модулю q.

Важный результат: два разных доказательства могут подходить к одним и тем же
матрицам. Они дают разные входы для хеширования, но это ещё не две независимые
возможности получить решение. Даже если каждая пара векторов независима, вся
тройка может зависеть друг от друга. Простое ограничение на примитивность
целочисленного вектора не устраняет пример с такой тройкой.

Математическая модель предполагает независимые равномерные матрицы. Для формулы
успешного хеша дополнительно предполагается независимость и равномерность хешей
при фиксированной матрице и полном наборе допустимых векторов. Эти предположения
не выдаются за доказанные свойства реального майнинга.

Проверки и результаты:

- Полный перебор 3957 матриц в 28 случаях совпал с точной моделью.
- Проверены 6144 разных реальных заголовка MGH1 по трём направлениям:
  nonce, новый родитель/высота и payload. Это заголовки, а не 6144 блоков цепи.
- Rust независимо проверил генерацию, допустимость векторов и хеши:
  42063 запроса с учётом первоначального поиска, без расхождений.
- На двух маленьких профилях найденные пулы переносились на новые заголовки;
  все первоначальные расходы сохранены, бесплатного поиска не предполагается.
- На профиле q=257,n=3,m=14 два запуска исчерпали бюджет без найденного вектора.
  Сохранены 8 миллионов операций перебора/пар; шесть зависимых серий явно
  пропущены. Отсутствие решений или криптографическая стойкость из этого не следуют.
- Полный локальный прогон: 189 тестов Python и 19 Rust, включая прежние
  межъязыковые проверки и проверки цепочки. GitHub Actions не запускались.

Следующий шаг — исследовать майнера, который меняет набор векторов и заголовки
адаптивно, сравнивая его с более сильными алгоритмами на одинаковых ограничениях.
Готовая формула веса цепи и безопасный retarget пока не выбраны. MagnetGate не изменён.
