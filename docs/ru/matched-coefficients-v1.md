# Пять задач: честное сравнение CPU и GPU для коэффициентов ±1/±2

Дата:09.10.2026. Английская документация — основная.

Сделаны пять задач: общий контракт поиска пакетами, C++/CUDA-ядро,
Python-интерфейс с освобождением ресурсов и учётом ошибок, независимые проверки
всего пространства кандидатов и измерения на локальной CMP50HX.

240 парных случаев ×3 повтора ×2 варианта дали1440 запусков без расхождений.
Прошли330 тестов Python,23 Rust и прежние наборы сверок. Дополнительно проверены
606832 позиции кандидатов на CPU/GPU,45890 положительных/отрицательных результатов,
22945 вердиктов независимого Rust-проверяющего и4978 полученных решений.
В предельном случае найдены все шесть поздних решений после18912 кандидатов.

Результат: в этом небольшом поиске CPU оказался быстрее в716 из720 пар.
GPU показал меньшее время только в четырёх. Медианы всех24 групп с новыми
матрицами также в пользу CPU. Теперь время включает одинаковые этапы для обоих
вариантов: подготовку, копирование, поиск, передачу масок, сборку результатов и
освобождение ресурсов. Отдельные проверки результатов идут вне этого замера.

Это не утверждение, что CPU всегда быстрее GPU. Здесь мало кандидатов,
сессия каждый раз создаётся заново, CPU однопоточный, частоты и фоновые процессы
не изолированы. Энергопотребление и зависимость от объёма памяти не измерялись.
Майнинг не работал; другие сервисы не останавливались. GitHub Actions не запускались.

Обработанные сверх лимита выдачи решения последнего пакета теперь явно учтены.
Журнал сохраняет завершённую работу при прерывании, а неопределённые результаты
не выдаются за нулевые. Ревью нашло и помогло исправить случаи потери учёта при
ошибке памяти и восстановления устаревшего журнала повторного запуска.

Этот этап — ограниченная проверка D5 нового критического плана. Преимущества
GPU в данной модели не показано; пригодность SIS для PoW остаётся открытым
вопросом. Дальше следует формализовать конкретную модель работы и пытаться
сломать её подбором лёгких матриц/заголовков, а не расширять набор ядер.
