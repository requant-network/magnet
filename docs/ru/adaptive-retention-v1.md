# Оплачиваемый выбор пула решений и подготовка GPU

Вторичное русское описание этапа от 2026-10-09. Основной документ:
[Paid adaptive retention](../research/adaptive-retention-v1.md).

Добавлена стратегия, которая при заполнении пула оценивает, какой вектор лучше
убрать для следующей новой матрицы. Она использует точную модель корреляций,
а не только количество решений. Вычисления выбора входят в окно запуска,
учитываются отдельно и ограничены 64 решениями на серию; затем явно включается
FIFO. Параметры консенсуса и прежняя стратегия FIFO сохранены.

Модель предполагает независимые равномерные будущие матрицы и условно независимые
хеши. Это исследовательские предположения. Нельзя применять вероятность для
заранее выбранного пула к той же матрице, из которой решения только что получены.

Проведено 336 запусков семи CPU-алгоритмов на трёх маленьких профилях: 306
завершились, 30 остановлены по времени. Из 84 пар FIFO/новая стратегия обе серии
завершились в 75; во всех 75 число успешных этапов одинаково. Девять неполных
пар не считаются равными. При этом новая стратегия действительно меняла пул:
520 из 1953 решений в завершённых запусках отличались от FIFO. Улучшение числа
успехов в этой серии не показано; дополнительные вычисления не бесплатны.

В завершённых сериях 652 успешных результата, ещё три сохранились в прерванных
контрольных точках. Это повторные лабораторные наблюдения, не 655 новых блоков.
Независимый Rust проверил генерацию, векторы, хеши и полный допуск каждого успеха:
40442 запроса без расхождений. Общие затраты прерванных запусков остаются
неизвестными. Одновременно с частью серии работали локальные проверки, поэтому
сравнение изолированной скорости оборудования по этим данным не делается.

Прошли 205 тестов Python и 19 Rust, форматирование, clippy и прежние межъязыковые
проверки. Исправлен контроль затрат: подмена внешних счётчиков теперь сверяется
с затратами алгоритма. В хеши исходников включены солверы и lock-файл FLINT.

На локальном Linux-сервере проверены CMP 50HX с 20480 MiB памяти, вычислительная
архитектура 7.5, рабочая видимость CUDA в существующем PyTorch и наличие nvcc.
Карта занята текущим майнингом; его не останавливали, пакеты не устанавливали,
секреты в репозиторий не переносили. GPU-майнер ещё не реализован.

Следующий этап — точная пакетная GPU-проверка решений с сопоставлением Python
и Rust, затем оплачиваемый поиск кандидатов. Для честного сравнения скорости
понадобится свободное окно GPU. [План GPU](../research/gpu-readiness-v1.md)
содержит ограничения арифметики и проверки. Производственная сложность,
вес цепи, retarget и денежные правила пока не выбраны.
